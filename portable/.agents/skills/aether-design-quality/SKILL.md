# Design quality

Use for a pre-release review or critique, not for a universal aesthetic score. Read [resource QA](../../../aether/knowledge/resources-qa.md), [distinctiveness](../../../aether/knowledge/distinctiveness.md), [strategy](../../../aether/knowledge/strategy.md) and [improvement loop](../../../aether/knowledge/improvement-loop.md).

1. Restate audience, task, brand evidence, device constraints and the chosen direction. Review the actual page/flow, not a generic inspiration checklist. Rank failures in task completion, truthfulness and accessibility ahead of polish.
2. Inspect hierarchy and specificity with real content; exercise navigation, forms, loading/error/empty states, section entry/exit/reverse scroll, and reduced motion only where the design uses them. Check small and wide widths, zoom, keyboard and slow hardware/network as relevant.
3. Record each finding as **context → reproduction → observed evidence → user impact → proposed fix → verification status**. Separate observations from hypotheses; do not mark an unrun screen-reader test or field performance metric as passed.
4. Choose the smallest improvement that fixes the underlying issue and name a retest. Log uncertain lessons as conditional suggestions for review rather than automatically promoting them to universal rules.

Deliver prioritized, reproducible findings and a concise retest plan. A screenshot alone cannot verify behavior, accessibility or speed.
