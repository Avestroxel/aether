# Self-improvement

Use after critique, launch, user testing or a failed design experiment. Read [improvement loop](../../../aether/knowledge/improvement-loop.md) and [resource QA](../../../aether/knowledge/resources-qa.md).

1. Restate the original intent and success signal. Collect actual feedback, completion/errors, performance and access barriers; label source, date, sample size and uncertainty.
2. Group findings by underlying task failure rather than screenshot-level opinions. Prioritize by severity, reach, frequency and cost; fix blockers first.
3. Write one testable hypothesis per change, a measurement and guardrails; avoid changing multiple major variables when attribution matters.
4. Record result, confidence, decision (keep, revise or revert), owner and next check. Store reusable lessons as conditional rules, not universal taste prescriptions. `learn` stores local contributions for review, not active instructions; redact personal data and secrets, verify third-party provenance and license, and request human review before changing shared guidance.

Example: 'Visitors miss the compare link' → move it next to plan cards → observe five plan-selection tasks and monitor comparison opens, while checking mobile focus order. Deliver a short decision log and next experiment. Never call a redesign successful solely because it looks better or a single vanity metric increased.
